Why static analysis alone is not enough

Open the Shop. Static analysis sees one ShopRow template. It cannot know how many rows the "server" sends, what they say, which are scrolled into view, or that a revisit creates brand-new rows. Only the running game knows.
The Golden Oven banner is declared in the files, but only appears after 25 coins of play. A template that exists is not a state you have reached.

What we can promise

We can promise that each snapshot is complete and every gap is counted. We cannot promise every screen was visited. The static template list turns that into a measurable number: templates seen ÷ templates declared.

Give the mirror more abilities

Toggling these changes only the mirror. Watch the sniffer: its data does not change. The extraction was already correct — what was missing was the ability to draw it.

Simulate conversion bugs we actually hit

The causes, one by one

Different renderer

The mirror is a generic drawer of rectangles, images and text. The game can run any code it likes to draw a pixel. Anything beyond the common vocabulary arrives as a name the client cannot execute.

Assets we deliberately do not send

Fonts are licensed. We send what the text says and how big it is, not the font file.

Things drawn by code

Custom meshes, particles and procedural effects exist only while the game's code runs. They leave a rectangle behind, not a recipe.

Outside the UI entirely

The 3D world is not in the UI tree. It is absent by definition, not by error.

Timing

An image is sent the first time it is needed, so the very first frame that uses it may arrive before the pixels do. Replay has every image up front — which is exactly why live and replay can differ on a few frames.

Geometry gate always reads 0% without bugs — because the mirror copies the final rectangle. That is the point: it proves the conversion is not distorting anything. It does not prove the mirror looks the same. That is what "fully redrawn" measures.

Who plays the game when nobody is watching?

To collect many UI states automatically, an explorer drives the game. Each run starts a fresh copy and takes 80 actions (every action is half a second of game time). Coverage is measured against the static template list.
